# 问题采集（微信版）

**版本**：v0.2（2026-10-21）

> v0.1 写成了两阶段正式访谈 + 表格 + JSONL，实际不会用——**给同学发一段 15 分钟的问卷，
> 回复率会很低，收到的东西还不如随便聊两句**。所以这一版改成：一条能直接发的微信 + 三列记录。
> 原版的研究设计只保留了一条真正重要的（第 2 节），其余删掉。

---

## 1. 直接发这条（复制即可）

> 想请你帮个小忙 🙏
>
> 我在做一个**设计知识库问答助手**：它从标准、材料数据表、工艺指南这类设计资料里找证据再回答，
> 每条结论会标"直接证据"还是"间接证据"，证据不够的时候它会直接说"不足以回答"，不编。
>
> 想问你：**过去一个月，你做设计/作业的时候，有没有为了确认一件事去翻资料、问人或者搜网页？**
> 比如标准怎么规定、某种材料能不能用、尺寸该取多少、某个工艺会不会出问题。
>
> 给我 **3~5 个你当时真的想问的问题**就行，越具体越好（带标准号或材料牌号最好）。
> 顺手说一下：当时你是怎么解决的、大概花了多久、最后拿到确切答案了吗。
>
> 答不出来也没关系——它现在挺慢的，而且我正好想知道**它答不出什么**。

## 2. ⚠️ 一个刻意的省略：**不要**列出库里有什么

v0.1 里有一段"库里现在覆盖这些块：GB 4806、Tritan、人体尺寸…"——**删掉了**。

原因：一旦对方知道库里有什么，他问的问题会往那儿靠。你收到的是"它能答的问题"，
而你要找的是"它答不出什么"。这样算出来的缺口 = 你本来就有的东西，是循环论证。

介绍里只说**资料类型**（标准 / 材料数据表 / 工艺指南），不说**具体有哪些标准、哪些材料**——
够他理解这是什么，不够他挑题。

> 如果对方主动问"都能问啥"，就说「设计上要查证的都行」。
> 他想先试用也行，但**让他先把自己那 3~5 个问题写出来再给链接**。

## 3. 对方回得很短时，追问这三句

| 他说的 | 你追问 | 你其实在拿什么 |
| --- | --- | --- |
| "想不到啊 / 我没什么问题" | "那你上周做的那个（XX），里面有没有要查证的东西？材料能不能用、尺寸依据哪来的？" | 真实问题 |
| 给了一个词，太笼统 | "这个你当时是查哪份资料确认的？还记得标准号或文件名吗？" | 来源线索 |
| "我一般都凭经验" | "那这个经验是从哪来的？有没有哪次发现自己记错了？" | **经验规则缺口**（库里那 11 个规则文件就是这么来的）|

第三句最重要：**"凭经验"往往就是最该被写成规则文件的东西**，而这类缺口补资料补不出来。

## 4. 你怎么记录（三列就够）

对方不用填表，你在自己这边记：

| 问题原文（一字不改）| 当时怎么解决 / 多久 | 现在能不能答 + 缺什么 |
| --- | --- | --- |
|  |  |  |

- **原文不要改写**。"怎么算都算不对" 和 "容量公式怎么推导" 是两个不同的问题。
- 「现在能不能答」**实际跑一次**再填，不要凭感觉。
- 攒够 **15 题以上**再看第 5 节的归类，不足就只做描述、不报比例。

## 5. 收完之后：缺口怎么归类

对**每一个"答不出"的题**，跑一次，然后按这张表归因——只有四类需要区分：

| 代号 | 含义 | 能不能靠补资料解决 |
| --- | --- | --- |
| `R1` | 需要的来源**不在库** | ✅ 补资料即可 |
| `R2` | 来源**在库但检不到**（任何深度都检不到）| ❌ 补资料没用，要改检索 |
| `R3` | 检到了，但**生成漏项**（提了类别没给数值）| ❌ 改提示词/契约 |
| `R4` | **缺规则文件**（"凭经验"那一类）| ⚠️ 要人写，不是买资料 |

**预登记的反直觉预期**：按项目已有的测量（16 条来源任何深度都检不到；77.6% 的 chunk 没有角色标签），
最可能的结果是 **`R2` 占多数**——那么结论就是"先修检索，不是先买资料"。

## 6. 已知局限

- **样本无代表性**：5 个同学、方便抽样，不能写成"设计师普遍…"。
- **只做描述**：15~25 题构不成任何统计检验，写"这 5 个人里有 3 个…"，不写"68% 的设计师…"。
- **"花了多久"是回忆值**，只能当量级（分钟级），不要当指标。
- 收不到**他放弃过、连查都没查的问题**——问卷法固有的盲区。
- 你在他旁边解释系统会污染他的提问 → 尽量让他先写完再聊。
